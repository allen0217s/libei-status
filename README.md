# 男主状态 · 独立状态面板 v2（本地候选版）

在原独立状态引擎上加入通用主角字段、按角色保存的规则和上下文条目编辑。界面与渠道交互仍来自 ST-BaiBai-Book 固定版本，来源和许可说明保留。

**本轮改动尚未推送或安装到真实酒馆。扩展管理器更新不会自动取得这些本地修改。**

- 原版 Vue/Shadow DOM 窗口、五套主题、桌面顶部胶囊导航、手机底部导航与抽屉。
- 状态更新可「跟随主 API」（酒馆主界面当前连接）或显式选择独立副渠道。没有失败自动换渠道。
- 添加/编辑/删除渠道、草稿关闭丢弃、拉模型/搜索、测试、温度/token/超时/思考强度/流式与排除参数。
- 世界书整本排除和条目备注名规则过滤，仅作用于本插件请求；不会禁用原书或正文注入。
- 悬浮书签、顶栏、聊天输入框上方、魔杖菜单、每楼状态查看入口。
- 状态使用「世界 / 主角」分区，不再要求指定角色名；旧「黎北」分区只做兼容读取。姓名或称呼独立配置。
- 原 v1 状态链、分支核对与导入导出格式保留；不同角色分别保存规则和初值选择，聊天进度仍按角色与聊天 ID 隔离。
- 变量规则页提供从上到下的可编辑条目，并分别预览插件更新模型上下文和正文模型的本插件注入段。

## 安装或从 v1 更新

1. **先在旧版导出完整状态存档和规则，备份酒馆设置。** 停用角色卡内旧状态脚本；不要同时启用旧卡内脚本和新版状态扩展。
2. 新用户在酒馆「扩展 → 安装扩展」粘贴：

   `https://github.com/allen0217s/libei-status`

   已安装此仓库的用户，在扩展管理中点「更新」，然后刷新酒馆页面。
3. 在魔杖扩展菜单打开「男主状态」。书签、顶栏、输入框上方和楼层入口可在「设置 → 基本设置」开启；它们默认与参考原版一样关闭。
4. 检测到旧版 API 配置时，明确选择导入草稿并检查后完成，或选择「不导入，明确跟随主 API」。不自动上传旧密钥，不删除旧数据。
5. 打开要跟踪的男性主角所在的单角色聊天，在变量规则页填写称呼、检查并手动选择初值。不根据名字推断性别，也不根据开场猜初值；暂不支持群聊。建议 SillyTavern 1.19.0+，通过 localhost 或 HTTPS 访问，以提供状态写入所需的 Web Locks。普通局域网 HTTP 可能只读。

手动安装时将仓库放入酒馆第三方扩展目录；[manifest.json](<manifest.json>)、[index.js](<index.js>)、[index.css](<index.css>) 保持在根目录。普通用户**不需要安装 Node、pnpm 或构建**。CSS 由插件内部载入 Shadow DOM。

## 设置及隐私

- 渠道、主题、入口与排除名单保存到当前 ST 账户的 `extensionSettings.libei_status_v2`，可能跨设备同步。
- **渠道密钥在点完成后按参考实现以明文写入酒馆设置，并非 ST secrets 加密保险库。仅在可信服务器使用。** 测试/拉模型会将草稿密钥经酒馆发给指定服务，但不保存草稿。关闭渠道弹窗丢弃未完成的修改。
- 不读写柏宝其他扩展的共享渠道或排除名单；安装两者不会互删渠道。
- 状态链与规则仍在原浏览器 localStorage 命名空间中，**不会随新设置自动同步**。换设备请导出完整状态存档。
- 状态/规则导出不含新旧 API 密钥。
- 世界书名单勾选即时保存；关闭名单弹窗不回滚。条目规则匹配 comment，不匹配正文内容。已进入历史正文的同样文字不会被追溯删除。
- 模板渲染默认关闭；打开后可能通过模板插件执行 EJS、读写变量，只对可信世界书开启。有排除规则却无法获得逐条世界书元数据时拒绝发送，而非无过滤降级。
- 主 API 沿用 generateRaw，无法保证独立即时中止，也不能观测其 finish_reason。取消/切聊天/切配置会丢弃过期结果，不强停酒馆主生成。副 API 可网络取消并拒绝 length 截断响应。

## 角色规则与模型上下文

规则按角色头像文件标识保存，不同角色不共用初值选择、更新规则或计算参数。已建立分区的角色改名不会丢规则；更换头像文件标识视为新角色，应导出后在新角色中导入对应规则和状态存档。旧全局规则只供原绑定角色兼容使用，不会套给其他男主。内部扩展 ID、存储键和文件格式名保留，避免升级后找不到旧数据。旧版本不认识新「主角」分区，回退请恢复升级前备份。写入权仍是当前浏览器内本插件的单标签页锁，不支持多个标签页同时写不同主角。

变量规则页的初值和上下文条目都可点击展开编辑；修改先留在草稿，保存才生效，导入也只先载入草稿。切换角色会丢弃旧角色未保存草稿，不会写进新角色。计算参数可直接编辑 JSON；自然语言描述不会自动改写程序公式。

插件更新模型使用：按排除规则收集的世界书参考 → 任务说明 → 跟踪对象 → 变量规则 → 数值事件规则 → 程序参数 → 输出协议 → 固定写入保护 → 前楼状态 → 本轮及最近消息。它并不自动复制正文模型的完整预设、人设和全部历史。

**正文能使用更新后的状态。** 结算提交后，插件重新注册当前状态注入段，供酒馆下一次正文生成使用；已生成的正文不会被追溯修改。正文收到跟踪对象、状态快照、可选的数值事件规则和正文职责说明，不会收到插件专用更新任务和输出协议。

页面的预览与实际发送共用组装函数。默认只预览草稿结构；点击“收集世界书参考”才扫描世界书。模板执行已开启时，预览拒绝扫描，以免执行 EJS 或写变量。预览不会发送模型请求、保存草稿或展示渠道密钥。正文预览只展示本插件的注入段，不代表酒馆最终完整请求，也不证明供应商已收到。

原生提示词聚合与样式加载以 [SillyTavern 1.19.0 固定源码](<https://github.com/SillyTavern/SillyTavern/tree/7e8663cd9c184a550b37238218bdd32c6efc68e9>) 为核验基线；用户实际安装版本尚未检测。未新增 MVU、Tavern Helper 或数据库插件依赖。

## 更新协议与数值结算

- 更新模型只输出一个 JSON 数组，不再要求 `<UpdateVariable>`、`<Analysis>` 或 `<JSONPatch>` 标签。旧标签输入仍可解析，但不能绕过数值字段的写入限制。
- 普通字段继续使用 `add / replace / remove`，路径直接相对于状态对象。数组还支持 `money` 收支事件及 `release` 消耗事件，因此它是本插件的更新协议，不是完整 RFC 6902。
- 模型负责判断本轮事件、金额和合规消耗量，并附本轮原文中的连续引文；程序负责余额、时间增长、非负处理及算式。引文匹配和范围检查不能保证模型的事实判断一定正确。
- 钱财、精液、精液算式只允许程序写入，替换整个「主角」对象也会被拒绝。任一事件无效时整轮不提交，不会只保存一半。
- 增长按本轮经过的整小时 × hourlyGain 计算，不足一小时不跨轮累计。新角色通用模板默认 hourlyGain=0，不把旧故事的每小时 +6 套给所有男主；已保存旧规则保留原参数。默认普通消耗区间 10～20，梦遗区间 20～40，均是可编辑的游戏参数，不是医学标准；程序不会因达到阈值就凭空生成事件，也不会偷偷把区间改成固定扣值。
- 支持连续“第N天”的跨日计算；同月的中文月日也可直接计算跨日；跨月或跨年须在起止状态中明确公历年份，例如 `2026-03-31`。缺少年份或自定义历法时拒绝猜测；需要先在尚未跨月的一轮明确年份。时间倒退也拒绝结算。
- 计算参数来自规则存档中的 `numericConfig`，不是从自然语言规则中执行公式。新角色默认值如下；可在变量规则页的“程序计算参数”条目直接编辑并保存。旧配置未写 moneyMax 时继续使用旧上限 100000，不会偷偷放宽；新角色默认使用程序支持的上限 1000000000000。修改「数值与事件规则」文字本身不会改变这些算术参数。

```json
{"version":1,"hourlyGain":0,"normalMin":10,"normalMax":20,"dreamMin":20,"dreamMax":40,"moneyMax":1000000000000}
```

收支事件结构为 `{"op":"money","direction":"income或expense","amount":整数金额,"evidence":"本轮引文"}`；消耗事件结构为 `{"op":"release","kind":"ejaculation或awake或dream","amount":单次消耗量,"count":实际次数,"evidence":"本轮引文"}`。`count` 可省略，默认为 1。示意中的「或」表示任选一个枚举值，不是实际填写内容。

升级会规范活动规则的协议和主角分区：原输出模板保留为 `legacyOutputFormat`，原版未改过的字段规则保留为 `legacyUpdateRules`；自定义字段规则、初值、当前进度及未知状态字段不删除。旧楼层快照不会追溯重算。新节点附带 `settlement` 结算依据，仍使用原有 v1 状态链、分支核对与存档位置。重复末楼重算仍以前楼为基准，不会在本楼新值上再次累加。

## 验证范围

本轮 `vue-tsc --noEmit` 与 Vite 构建通过；原有 5 项初值回归、36 项 API/设置/世界书测试通过。另用独立临时脚本执行了 19 项主角规范化/协议/数值检查和 18 项隔离 Chrome 集成检查，均通过：包括双角色隔离、旧草稿拒存、预览与实际请求逐字一致、更新状态注册到正文注入段、无副作用草稿预览、键盘展开和 390/320px 无溢出。浏览器只使用内存数据与模拟 API，不等于真实酒馆验收。仓库保留的旧 19 项报告和上一轮检查结果都只作历史证据，不计本轮通过项。

通用 manifest 校验器因既有 `css: ""` 策略报错，**该检查未通过**，另提示 Extras 字段已弃用。本插件故意不向宿主全局载入 CSS，而在 Shadow DOM 内自行加载样式；[1.19.0 原生加载器](<https://github.com/SillyTavern/SillyTavern/blob/7e8663cd9c184a550b37238218bdd32c6efc68e9/public/scripts/extensions.js#L781-L784>) 明确允许空值。此次保留原策略，没有改校验器或为消除报错去全局注入样式，不据此宣称扩展发布验收通过。

参考路由快照为 2026-08-18，已按动作读取 A0、C2/D7、C4/C7、D5/E5，并以固定宿主源码补充接口依据；未选择或引入外部设计组件。

**尚未在用户真实酒馆/真实供应商 API 中测试。** 建议先手动更新一个楼层确认后再启用自动更新。

## 源码与开发

运行资源位于仓库根目录，完整 Vue/TypeScript 源码在 [src](<src/>)。旧状态适配器已固定为源码，不依赖原开发工作区重新生成。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm run typecheck
pnpm run build
pnpm test
pnpm run test:browser
```
