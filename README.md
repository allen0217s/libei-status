# 黎北 · 独立状态面板（酒馆原生扩展 v1.0.0）

这是黎北专用的轻量 SillyTavern 前端扩展，不是服务器插件，不是 SQL 数据库。状态功能不需要 MVU 或酒馆助手，不改酒馆主模型连接或预设。

## 安装到 SillyTavern

1. **先备份**：旧版用户在旧面板导出「完整存档」和「规则与配置」。
2. 停用旧的黎北状态脚本及旧 MVU/Zod，刷新酒馆；不要同时运行两套状态更新。
3. 在酒馆「扩展 → 安装扩展」粘贴本仓库链接：

   `https://github.com/allen0217s/libei-status`

4. 安装后刷新页面，在扩展管理确认「黎北 · 独立状态面板」已启用。
5. 打开名称为「黎北的府邸生活」的单人聊天，点击悬浮「府」字，或魔杖菜单的「府 · 黎北状态」。扩展设置中可以隐藏悬浮球。
6. 在「API设置」填写独立 OpenAI 兼容地址、模型和密钥，保存并测试。正文仍使用酒馆原来的主连接。

本仓库仅发布扩展及默认初值/规则，**不包含用户聊天、浏览器存档、API 密钥或完整角色卡**。请使用配套的插件专用卡；如沿用原卡，务必停用其中旧的状态脚本。人物管理脚本不是本扩展的一部分。

也可下载仓库，把根目录文件放到 `public/scripts/extensions/third-party/libei-status/` 下，确保 `manifest.json` 位于该目录的直接下层。此目录不是服务器插件，无需安装 npm 包或运行构建。

本扩展提供默认角色设定和变量规则。公开仓库中不要提交自己导出的聊天、存档、私密配置或密钥。

## 三个页面

- **当前状态**：当前与历史楼层快照、手动更新/重算末楼、完整存档导入导出、分支清理。历史楼层只读。
- **变量规则**：三套初值、更新规则、输出格式、数值事件规则、正文状态模板，支持 YAML/JSON。保存规则不会重置现有进度。
- **API设置**：独立 Chat Completions 地址、模型、密钥、自动更新、上下文条数、Token、温度、超时和正文提示选项。

开场使用匹配初值，不调用更新 API。正常一轮正文完成后，独立 API 返回 JSONPatch，校验成功才保存。切换回复、改写前文或删除消息，会按完整正文来源链退回匹配状态；旧分支保留时可复用，缺失时需要补算。手动重算末楼从前一楼重新计算，不重复累加。

自动更新只跟随完整的正文生成结束，停止生成、编辑、仅切换已有回复、后台 quiet 生成、dry run 和打开旧聊天不会主动消费更新 API；有缺口可手动补算。自动最多补三楼，更多需要手动确认。正文含旧变量更新命令时暂停结算，避免双引擎更新。

酒馆在命令消费或连接预检失败时不一定发出结束事件。若酒馆已经**明确结束处理**，但面板仍认为在生成，可在「当前状态 → 存储管理」点「恢复正文生成标记」并确认。它先检查酒馆原生生成状态，不会打断主模型，也不会自动补算；仍在等待慢网络预检时不要使用，长推理也不要按等待时长猜测结束。

## 旧版迁移

本版故意沿用旧版的存储命名空间与状态格式。在**相同浏览器 + 相同酒馆地址/端口 + 相同角色头像标识 + 相同聊天 ID**下，停用旧脚本并刷新后可读取原存档。旧的助手转发选项会在内存中解释为「直连」，旧记录不会因此被自动重写；请在 API 页重新检查并保存。

- 旧聊天继续玩：保留原角色和头像标识，停用卡内旧状态脚本，不必为了用扩展强行新导入角色卡。
- 使用新的插件专用卡：酒馆可能给它新的头像标识；如找不到旧进度，在对应聊天中导入之前导出的**完整存档**。导入只采用正文链匹配的节点，不匹配会拒绝。
- 换设备/地址：先备份聊天记录、完整存档、规则配置；恢复聊天后分别导入两份面板备份。配置导入会清空已保存密钥，请重新填写。
- 不会读取 MVU 消息变量来猜测状态，也不会自动把单楼快照当完整存档。

## 依赖与限制

- 建议新版 Chrome/Edge，以 **localhost 或 HTTPS** 访问酒馆。需要 Web Locks 才能写入；普通局域网 HTTP 通常没有 Web Locks，会只读，不冒险抢写。不要用禁用浏览器安全功能作为解决办法。
- 只支持名称为「黎北的府邸生活」的单角色聊天；群聊及其他角色不注入这套状态。请勿随意改角色名。
- 原生接口依据 SillyTavern release 1.19.0 源码核对；并未宣称支持所有旧版或第三方分支。缺少原生事件或提示接口时会报错停止。
- API **仅支持浏览器直连 OpenAI 兼容 Chat Completions**，服务需允许 CORS；HTTPS 酒馆访问 HTTP API 也可能被浏览器拦截。本版不包含助手转发或服务器代理，也不支持原生 Anthropic Messages/Responses 端点。
- 这张卡另有独立的**人物管理/录入脚本**，原样保留。它仍需要酒馆助手；如果不用人物录入，可停用该脚本，不影响状态插件。不要把“状态功能无助手依赖”误解成已经重写人物管理功能。
- 同源其他脚本仍可能读取浏览器存储。密钥默认只在内存；选择记住会明文落盘，不会出现在本扩展的状态/规则导出中。
- localStorage 不会随酒馆角色卡或聊天导出自动携带，卸载插件也不会主动删存档。完整存档包含剧情片段和私密状态，请保管好。

## 验证与首轮验收

本版本通过 35 项核心与集成模拟测试；[测试报告](validation/test_report.json) 记录对应代码的 SHA256。覆盖状态链、原生事件、三页 UI、API 请求、重算、停止/过期请求、切聊天提示清除、旧配置迁移、只读与卸载。测试使用模拟 DOM 和本地假 API，**没有连接你的真实 API，也未在你实际的酒馆里验证视觉及插件组合**。

首次请用测试聊天按顺序检查：开场初值 → 保存并测试独立 API → 一轮正文后自动更新 → 重生成/切回复 → 切到其他角色不注入 → 导出完整存档再导入。若遇错，保留报错信息及酒馆版本；不要清网站数据来“修复”。
