# 通用状态协议 v1（插件 3.x）

## 输出

生成模式共用同一解析器。推荐每次回复输出一个完整的 `<status>` 块：

```text
<status>
{"mode":"full","state":{"角色":{"心情":"平静","好感度":50,"衣着":["衬衫"]}}}
</status>
```

之后可提交增量：

```text
<status>
{"mode":"delta","state":{"角色":{"好感度":55}}}
</status>
```

块内可用 YAML，亦可带一个 JSON / YAML 代码围栏。最外层必须是对象。作为便利输入，单独的状态对象视为 full；随正文提取时必须有完整状态标签。首次没有旧状态时，拒绝 delta。

- full：整个状态替换，允许保留值为 null 的字段。
- delta：JSON Merge Patch 语义；对象递归合并、数组整体替换、null 删除对象键。需把字段设为 null 时使用 full。
- 不支持旧 JSONPatch、money、release 等程序事件。
- 每条回复只允许一个状态块；多块、嵌套、缺少结尾或解析失败时整轮拒绝，不写入一部分。
- 使用 YAML 1.2 core，拒绝重复键、锚点、别名、显式标签、原型键、非有限数值和非 JSON 类型；不执行宏、EJS 或脚本。
- 单份状态/模板最多 25 万字符、16 层嵌套和 12000 个数据节点。

## 生成

随正文模式通过 `SillyTavern.getContext().setExtensionPrompt` 注入一次状态任务。注入位置 IN_CHAT、角色 SYSTEM，深度可选 0–10，默认 0，关闭世界书扫描。状态输出仍占用 token。

独立模式通过现有 API client 发送系统规则与一份 JSON 参考资料。参考资料包含当前角色的名称、描述、性格、场景，以及最近 1–30 条消息（默认 3），过滤系统消息和完整状态块。不读世界书，不展开参考资料中的宏。当前状态来自目标回复之前的有效快照；重算同一楼层不会把该楼层上次生成的状态再累加一遍。

自动处理仅在新回复完整结束后进行。quiet 请求不触发新的自动请求；重复通知不重复写入。停止生成后不自动提取，需用户核对后手动操作。多个跳过的楼层可能超过参考消息窗口，此时应扩大窗口或手动修订状态。

## 所有权与保存

| 数据 | 位置 |
| --- | --- |
| 预设库、界面偏好、生成方式、渠道 | extensionSettings.libei_status_v2 |
| 预设绑定、当前状态、上一状态、历史快照 | chatMetadata.libei_status_data |
| 导航页偏好 | 原有本地导航键 |
| 2.x 原始状态与规则 | 原 localStorage，只读迁移，保留原值 |

从已打开的聊天读取元数据时允许聊天文件改名，后续保存会更新所记聊天 ID；外部存档导入仍严格核对归属。新版只修改自身的聊天元数据键，并调用宿主 saveMetadata。写入前复核角色、聊天、元数据对象、原数据修订及请求捕获的配置和对话。保存抛错时还原内存中的原键值。宿主 saveMetadata 没有统一的服务端成功回执，本地模拟不能代替实际保存验收。

每条快照记录预设期次、回复楼层、swipe、完整对话前缀指纹、状态和上一状态。编辑/删除前文或换 swipe 后，只显示当前分支仍匹配的快照；历史查看可显式选取保留的旧分支。指纹仅用于内容匹配，不是安全签名。

切换预设开始新期次，既有快照继续保留。最多 80 次快照；档案总量超过 400 万字符则停止写入，提示先导出和清理。通过原生 Web Locks 保持同一来源仅一个页面可写，销毁时释放；其他页面保持只读。缺少该能力时仅允许查看。此锁不跨设备协调。

## 展示与生命周期

使用 Vue 文本插值展示模型值，不执行状态中的 HTML。比例、百分比和常见评分可显示进度条；只有约定的 100 分回退会带提示，未知高上限的数值不会被假定为 100。

状态隐藏使用宿主 messageFormatting 重绘已去除状态块的正文，保留原始显示供关闭时恢复。只在单角色聊天、插件启用、随正文模式下运行；格式无效时不隐藏。移除监听器、清除自身注入并恢复显示是销毁流程的一部分。

外部宏、角色专属脚本、MVU 及世界书流程不由此协议执行。2.x 程序字段和权限不会因导入模板而继续生效。
